Portico · Strategic Migration Plan

Native Chat: removing Docker/OrbStack & Open WebUI

Replace a 9-service Docker stack and a patched Open WebUI fork with a chat experience built natively into the Electron app — an OpenAI Agents SDK runtime, a native React UI, one local SQLite store, and host-native sandboxed execution — at full feature parity.

Approved · Workbench gpt-5.6-sol (ultra) round 8 + internal 4-critic review 8 adversarial rounds 11 → 0 blockers Strangler migration · M0–M7

03

Five new components

the target architecture
01

Agent Runtime

@openai/agents in a Node-22 utilityProcess. Ports the context engine, tool loop, confirmation gate, steering, subagents & scheduling out of OWUI middleware.

02

porticoMcpToolAdapter

Reproduces mcp-orc's exact 103-tool name manifest, wraps every call in the gate, injects trusted identity via MCP _meta, vends broker credentials per request.

03

Native Chat UI

React on a sandboxed, separately-originated app://chat document with a minimal preload; streams over IPC MessagePorts. O(delta) rendering.

04

Local Store

One node:sqlite DB in a dedicated storage worker — replaces webui.db, Redis & Mongo. Durable per-chat state; instr()-based search.

05

Host Execution

MCP servers & code-exec as host processes under @anthropic-ai/sandbox-runtime — one sandbox per server, read-deny-by-default, descendant-tracked watchdog.

LLM routing — the Agents SDK is OpenAI-shaped; two of three providers are not

Three custom Model adapters replace Bifrost, speaking llm-proxy's native protocols directly: Bedrock Converse (Atlas — ports converse.rs stream repairs, adaptive thinking, cache points) · OpenAI Responses (GPT-5.x — instructions hoisting + tool-namespace caching) · Vertex (Gemini). All carry the 7 x-portico-* headers & the Keychain-backed key.

Phasing

strangler sequence — opt-in native stack, then cut over & delete Docker
M0

Enablers

Tolerant updater (schema-3) + capability-version telemetry to fleet saturation; state exporter ships in the last Docker-full release.

Gate: Docker-free payloads safely receivable everywhere.
M1

Native vertical slice (hidden)

Chat UI + runtime + model gateway + store behind a dev flag; streamed multi-provider chat; tools via the adapter against packaged core binaries.

Gate: P0 smoke + §I model-gateway parity; cache-hit & streaming perf ≥ current.
M2

Middleware parity

Context engine, skills, gate + chips + allowlists + scheduled-run provenance, steering, subagents, observability bus. Core servers de-Redis'd.

Gate: §D/§G + gate suite; consistency runners at current pass rates.
M3

UI parity

Full shell: search, artifacts panel, scheduled-tasks pages, settings, prompt library, deep-link routing, diagnostics.

Gate: §B/C/E/F/M/N; V-005/V-011 XSS corpus; perf budgets.
M4

Exec & artifacts native

Read-deny srt exec + descendant watchdog + per-chat overlays + sandboxed artifact supervisor.

Gate: §J + artifacts; sandbox security review; threat-model-delta sign-off.
M5

MCP fully host-native

All feasible integrations + user servers on per-server sandboxes; OAuth container-free; bridge re-targeted & gated; marketplace re-targeted.

Gate: §G/§H; OAuth e2e matrix; per-server secret-isolation + direct-port-bypass tests.
M6

Migration & cutover

Journaled one-time migration under a maintenance barrier; scheduling lease transfer; native default. Beta first, forward-fix.

Gate: shadow-import ≥99.5% (entry) & migration ≥99.5%; rollback-after-migration green.
M7

Deletion

Stable rollout; delete the Docker estate; OrbStack/image reclaim; EOL-redirect stragglers; retire legacy installer. One permanent rescue build kept.

Gate: full §L security sweep; §A/§K final.
05

How the plan was hardened

eight adversarial review rounds to mutual sign-off

Blocker-class findings per review round

Workbench CLI (gpt-5.6-sol, ultra) + internal 4-critic workflow · each fix verified against the repo, not just claimed

Round 1 · 11 blockers

Tool-name manifest coupling, chat-UI isolation, read-deny sandbox, state exporter, marketplace estate, dual-stack scheduling, rollback fence…

Rounds 3–4 · deep corrections

Seatbelt is a filter not a namespace (path contract migrated); servers trusted model chat_id (identity now injected); 8080 port collisions.

Rounds 5–7 · the long tail

Capability-selective fleet handoff; loopback ≠ private without a netns; cookie vs opaque-origin iframe; export credential leakage — each verified in-repo.

Round 8 · APPROVE

Zero blockers, zero unresolved findings. Residuals are explicitly-accepted trade-offs or named implementation spikes.

07

Non-negotiables & honest limits

hard-won from the incident record + the review
Invariants the rewrite must preserve
  • The tool-confirmation gate runs below the model on every dispatch route — including the external-client bridge and dev test-invoke.
  • Structured contentBlocks are the model-facing source of truth; display strings never are.
  • Server-side identity is never model-authored — the runtime injects trusted chat ids; a turn in chat A can't act on chat B.
  • One readiness oracle for prompt-building, spec attachment & dispatch; a bad stored tool name must never brick a chat.
  • Per-chat state is durable, never evicted; streaming render is O(delta) with one scroll writer.
Explicitly-accepted residuals (signed off)
  • Loopback ≠ private without a netns: artifact inner servers need a targeted microVM, or a documented same-UID residual with compensating controls.
  • No aggregate 2-CPU ceiling for a host process tree (VM-only property); CPU bounded by cumulative-time + wall-clock kill.
  • Pre-floor installers can't honor a rollback fence added after they shipped — bounded by the permanent Docker-full rescue build.
  • LibreOffice and a VM-vs-sandbox exec backend are named open decisions gated on Spike D.
