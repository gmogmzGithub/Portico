# Release Notes: Hardening and Bug Fixes (`dc617cf`)

## Overview

This release introduces a new **pending chat work / user steering** system that lets users queue follow-up prompts and steer the assistant mid-conversation, alongside a comprehensive **Agent VM tool renaming** that simplifies all VM-related tool names. The remainder of the changes harden the Electron shell, Bifrost proxy, OrbStack installation flow, and several frontend components.

---

## 1. Pending Chat Work & User Steering

The largest addition in this release is a full-stack system for managing queued user prompts and mid-stream "steers" (instructions injected while the assistant is still generating).

**Backend** (`pending_chat_work.py`, `tasks.py`, `chats.py`, `middleware.py`, `main.py`):
- New `pending_chat_work.py` module (~1,200 lines) provides Redis-backed state management for per-chat pending steers and queued prompts, with optimistic-locking, drain scheduling, and socket.io notification emission.
- New `tasks.py` module wraps async task lifecycle (create, get, list, stop, cleanup) with Redis persistence and adds a `task_id`-aware creation path so pending-work drains can skip the currently-running task.
- Seven new REST endpoints on the chats router (`GET/PUT/DELETE` for pending steers, `POST/PUT/DELETE` for queued prompts, `GET` for full pending-work state) with Pydantic request models.
- Middleware integration: on both follow-up and continue code paths, the middleware now consumes the pending steer from Redis, injects it into the conversation messages, and merges any attached files. At terminal completion and on error/cancel, a drain is scheduled to pick up the next queued prompt automatically.
- New `user_steer` content block type handled in message serialization: when encountered, it splits the assistant turn, emits the steer as a user message, and resumes a fresh assistant turn.

**Frontend** (`chatPendingWork.ts`, `pendingChatWork.ts`, `Chat.svelte`, `MessageInput.svelte`):
- New `chatPendingWork.ts` API client with typed interfaces for the seven pending-work endpoints.
- New `pendingChatWork.ts` utility module (~360 lines) with hotkey resolution (Alt+Enter to queue, Alt+Up/Down to navigate edits), preview text generation, reconciliation helpers, and sorting logic.
- `Chat.svelte` gains ~100 lines for hydrating/normalizing assistant messages and wiring pending-work state into the chat lifecycle (load, poll, reconcile backend-started turns).
- `MessageInput.svelte` adds a visible "pending steer" pill and a "queued prompts" list above the composer, inline edit/cancel/save UX, and keyboard shortcut integration.

## 3. Bifrost Bridge Hardening

- **OpenAI metadata sanitization**: When a request is routed to an OpenAI-compatible provider (detected via `x-openwebui-chat-id` / `x-openwebui-message-id` headers), the `metadata` field is now stripped from the payload before forwarding. OpenAI rejects unknown top-level fields, and Open WebUI injects `metadata` unconditionally.
- **Prompt cache affinity fallback**: For OpenWebUI-originated OpenAI requests, prompt cache affinity is now extracted from the payload body if not present in headers, ensuring cache configuration isn't silently lost.
- **Claude Sonnet 4.6 pricing**: Formatting-only fix for the Sonnet 4.6 cost entry (no price change).
- New test: `chat_completions_handler_strips_openwebui_metadata_for_openai_requests`.

## 4. Upstream Retry Status Events

When the model provider stalls or returns a retryable error, the middleware now emits visible status events to the frontend:

- A "Model provider stalled; retrying (attempt N/M)" status appears during retries.
- A hidden "Recovered after upstream retry" status is emitted on success after retry.
- New `chatStatusHistory.ts` utility tracks and deduplicates status entries by `status_key`, with `observed_at` timestamps.
- `ResponseMessage.svelte` status type expanded with `error`, `hidden`, `observed_at`, `queries`, and `status_key` fields.

## 5. Mac Architecture Guard

New `mac-arch-guard.js` service detects hardware/package architecture mismatches on macOS (e.g., running an Intel-packaged build on Apple Silicon). If a mismatch is detected in a packaged build, the app shows a dialog explaining the issue and exits, preventing subtle performance or compatibility problems. Includes comprehensive unit tests.

## 6. Chat Export Download Handling

New `owui-downloads.js` service intercepts `will-download` events from the OWUI session and routes PDF, TXT, and JSON chat exports through a native save dialog with appropriate file type filters and default filenames. Previously, exports went through the default Chromium download behavior.

## 7. OrbStack Installation Hardening

- `install_v2.sh`: New `prepend_path_once()` helper prevents PATH duplication; `ensure_orbstack_cli_on_path` is called before Docker readiness checks; `wait_for_orbstack_docker_ready` replaces inline polling loops.
- `prereq-docker-setup.sh`: New `orbstack_appears_installed()` function checks both `/Applications/OrbStack.app` and `brew list --cask`; `finalize_orbstack_install()` consolidates post-install validation; graceful handling when Homebrew reports an error but OrbStack is actually present.
- New test: `test_prereq_docker_setup.sh`.

## 8. Electron Focus & Interaction Improvements

- `chat-tab.js`: New `focusActiveOwuiView()` function forwards focus to the correct OWUI view, respecting interaction suppression state.
- `owui-host.js`: Exposes `isOwuiInteractionSuppressed()` globally for focus-gating.
- `conversation-window.js`: Window `focus` events now propagate to the underlying OWUI view.

## 9. Model Selector UI Refinements

- `modelBranding.ts`: New `getModelSelectorLogoPresentation()` function centralizes logo sizing, wrapper classes, and dark-badge logic for both `compact` and `grouped` variants, replacing scattered inline logic.
- `ModelItem.svelte` and `Selector.svelte` now consume the centralized presentation object.
- Claude Sonnet 4.6 added to `model-traits.ts`.

## 10. Middleware & Message Terminal Ordering Fix

The `chat:completion` event and database upsert are now emitted **before** background tasks run, and `schedule_terminal_pending_chat_work_drain` is called immediately after terminal completion. Previously the completion event fired after background tasks, which could delay pending-work drain pickup.

## Top 3 Manual Testing Focus Areas

### 1. Pending Chat Work & User Steering (Highest Priority)

This is the largest new feature and spans every layer from Redis state to the composer UI.

- **Queue a follow-up prompt** while the assistant is streaming (Alt+Enter or the queue button). Verify the queued prompt appears as a pill above the composer and auto-dispatches after the current turn completes.
- **Steer mid-stream**: While the assistant is generating, type a steer and submit it (Enter). Confirm the assistant acknowledges the steer in its output and the steer pill disappears.
- **Edit/cancel queued prompts**: Use Alt+Up/Down to navigate queued prompts, edit one, save it, then cancel another. Verify the queue state updates correctly in the UI and persists across page refreshes.
- **Multiple queued prompts**: Queue 2-3 prompts, let them drain sequentially. Verify each fires in order and the conversation history is coherent.
- **Error/cancel recovery**: Cancel a streaming response that has queued prompts pending. Verify the drain still picks up remaining queued work.
- **Steer with file attachments**: Attach a file to a steer and verify it's included in the follow-up context.

### 2. Agent VM Operations with Renamed Tools (High Priority)

Every Agent VM tool name changed in this release. Regressions here would break code execution, artifact creation, and file operations.

- **Create a VM and execute code**: Trigger a code-execution skill (e.g., "write and run a Python script"). Verify VM creation, code execution, and output rendering all work end-to-end.
- **File operations**: Create, read, edit, and delete files inside a VM. Verify workspace copy-to/copy-from still produces download links.
- **Disabled tools**: If any VM tools are disabled in your tools config, verify they remain disabled after the rename (the canonicalization layer should map legacy names).
- **Overflow handling**: Trigger a large tool result that causes overflow. Verify the overflow hint references `grep_file` and `read_fragment` (not the old names) and that the model can follow those instructions.
- **Artifacts workflow**: Run an artifacts skill that creates files in the workspace. Verify the full create-file-then-download flow.

### 3. Bifrost Proxy & Upstream Retry Behavior (Medium-High Priority)

The metadata stripping and retry status changes affect every LLM request routed through Bifrost.

- **OpenAI model requests**: Send a chat message using an OpenAI model (e.g., GPT). Verify the response succeeds (metadata stripping prevents 400 errors from OpenAI rejecting unknown fields).
- **Anthropic model requests**: Send a chat message using a Claude model. Verify metadata and prompt caching still work correctly (Anthropic requests should NOT have metadata stripped).
- **Retry visibility**: If possible, simulate or wait for a provider stall. Verify the "retrying" status appears in the chat UI and resolves to "Recovered" on success.
- **Cost tracking**: After sending messages to both OpenAI and Anthropic models, verify cost/usage numbers are still reported correctly in the LLM debug monitor.
