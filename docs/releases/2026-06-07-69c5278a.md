# Release Notes: Host MCP Bridge and Secret Broker (`b8a971d3`, `69c5278a`)

## Overview

This combined release note covers two closely related commits:

- `b8a971d3` — Host MCP Bridge bearer-token auth, app-managed MCP client auto-configuration, Claude Opus 4.8 support, artifact version previews, sensitive-info VM isolation, and UI/test polish.
- `69c5278a` — scoped secret broker architecture, Electron `safeStorage` OAuth migration, OWUI auth bridge, MCP client config removal/reveal actions, and runtime-secret lifecycle hardening.

The bridge work in `b8a971d3` establishes an authenticated local MCP gateway. The broker work in `69c5278a` reuses that gateway as a scoped host boundary for OAuth access-token and static-secret vending.

---

## 1. Host MCP Bridge Bearer Auth and Auto-Config

`b8a971d3` made the Host MCP Bridge an authenticated local MCP endpoint for external clients.

Key changes:

- `/mcp` now requires `Authorization: Bearer <token>`.
- `/health` remains unauthenticated for Electron liveness checks.
- Electron generates per-client bearer tokens and stores raw tokens in app-owned private token files.
- The bridge auth registry stores salted SHA-256 hashes, not raw tokens.
- The Rust bridge validates bearer tokens with constant-time hash comparison and ignores revoked registry entries.
- Bridge launch now passes `--auth-registry`.
- Stdio proxy mode supports reading a remote auth token from an PORTICO-owned token file.

The app-managed configuration flow detects and configures:

| Client | Configuration strategy |
|---|---|
| Claude Code | Streamable HTTP with `headersHelper` token reads |
| Claude Desktop | Local stdio proxy forwarding to the streamable HTTP bridge |
| Codex | Direct streamable HTTP config in `config.toml` |
| Cursor | Direct streamable HTTP config in `mcp.json` |
| Amp | Direct streamable HTTP config in Amp settings JSON/JSONC |

Documentation:

- User/operator guide: [`../MCPBridge.md`](../MCPBridge.md)
- Maintainer architecture: [`../architecture/mcp/host-mcp-bridge.md`](../architecture/mcp/host-mcp-bridge.md)

## 2. Scoped OAuth and Static-Secret Broker

`69c5278a` extended the Host MCP Bridge into a scoped secret broker for MCP runtime containers.

Key changes:

- Replaced Docker-secret/bind-mounted durable OAuth token directories with broker endpoints:
  - `/secrets/oauth/access-token`
  - `/secrets/static-secret`
- Added scoped bridge tokens:
  - `oauth:access-token:<server_id>`
  - `static-secret:<server_id>:<secret_name>`
- Generated Docker Compose services receive broker URLs and per-server/per-secret token env vars instead of broad host token mounts.
- `portico_STATIC_SECRET_TARGETS` describes static-secret materialization targets for container startup.
- Static secrets are fetched through the bridge and written inside the owning container with private permissions.

Documentation:

- Secret broker architecture: [`../architecture/auth/mcp-secret-broker.md`](../architecture/auth/mcp-secret-broker.md)

## 3. Electron safeStorage OAuth Migration

`69c5278a` moved durable MCP OAuth records into Electron `safeStorage`.

Key changes:

- OAuth records persist under Electron app `userData` as encrypted records rather than plaintext token/client files mounted into containers.
- Legacy `mcpo-oauth-tokens` and `mcpo-core-oauth-tokens` records are migrated through the new `mcp-orc export-legacy-oauth-record` command.
- Migration verifies the safeStorage round trip, removes legacy files, and records per-server migration status.
- The Rust file-at-rest XOR/HMAC encryption layer was removed because durable OAuth records no longer live in the Rust/container token store.
- Runtime OAuth token files are short-lived runtime material only.

Operational note: if safeStorage is empty and no migratable legacy record exists, the broker returns `auth_required`; first-time OAuth must bootstrap a durable host-side record before broker-vended runtime startup can succeed. This bootstrap path was completed in follow-up work (single-server `--oauth-bootstrap` mode plus the `/oauth/bootstrap-record` export into safeStorage); see [`../architecture/auth/mcp-secret-broker.md`](../architecture/auth/mcp-secret-broker.md).

## 4. OWUI Auth Bridge

`69c5278a` switched Open WebUI to authenticated mode while keeping Electron-owned user session bootstrap.

Key changes:

- Added `portico_auth_bridge.py` FastAPI router.
- Open WebUI now runs with auth enabled and password/login/signup disabled.
- Electron posts a human session to OWUI and seeds frontend auth through a nonce-protected handoff page.
- New Electron services manage OWUI auth readiness, session seeding, and frontend verification.
- Runtime secrets now include `OWUI_AUTH_BRIDGE_SECRET` and `WEBUI_SECRET_KEY`.

## 6. Artifact Version Preview Snapshots

`b8a971d3` added immutable per-version artifact preview snapshots.

Key changes:

- `materialize_version` writes both the current workspace and `_version_workspaces/<artifact>/v<N>/`.
- Electron added `artifact-preview.js` with path traversal checks and chat/artifact ownership validation.
- New preview route serves `/artifact-preview/:chatId/:artifactId/versions/:version/*`.
- Renderer artifact panels and detached windows prefer version snapshot URLs and bypass cache on version switches.
- Browser-unsafe port `10080` is skipped for artifact host-port allocation.
- Artifact list/status handlers refresh stale running metadata before reporting.

---

## 7. Sensitive-Info VM Isolation

`b8a971d3` changed sensitive-info handling for Agent VM/code-execution workflows.

Key changes:

- Sensitive files are uploaded directly into running Agent VM containers using Docker upload-to-container tar archives.
- Sensitive cleanup and redaction became async so they can operate on VM-resident files.
- `SensitiveFileReference` and `SensitiveWorkspaceTarget` replaced ambiguous tuple dispatch.
- The `request_sensitive_information` tool spec and modal copy avoid exposing internal concepts such as Agent VM, sandbox, or `/work`.

---

## 8. Claude Opus 4.8 and Prompt Cache TTL

`b8a971d3` added Claude Opus 4.8 support across catalog, Bifrost, frontend model metadata, and test runners.

Key changes:

- Added `Claude Opus 4.8` to `model_catalog.yaml` with 128K max output.
- Added reasoning-effort options including `xhigh`.
- Added frontend capabilities, traits, and pricing.
- Bifrost reads `claude_prompt_cache_ttl` from the catalog and applies Bedrock `CachePointTtl` to cache-point blocks.
- Reasoning stream translation de-duplicates cumulative reasoning deltas.
- New headless chat consistency runners validate Opus 4.8 prompt-cache TTL/locality and reasoning stream behavior.

## 9. DB Repair, Guided Setup, and UI Polish

Other notable `b8a971d3` changes:

- DB repair now sanitizes invalid `meta` columns as well as invalid `chat` payloads and creates a corrupt-meta backup table.
- Guided setup tracks pre-configured servers and shows "Already configured" cards instead of prompting again.
- Preset env vars from server definitions are merged into setup state while sensitive keys/placeholders are excluded.
- Save-and-continue now surfaces per-input save failures.
- Activity/thinking/composer shimmer effects were replaced with color-pulsing spotlight animations.
- Busy spinners were slowed for less visual noise.
- OAuth wizard test steps were redesigned as a card/grid flow with retry affordances.
- Chat load failure now clears busy/generating/rate-limit overlay state.
